## 멘토링 목표

현재 ClaFact는 뉴스 속 수치 주장을 KOSIS 공식 통계와 대조하고, 근거·판정 과정까지 남기는 검증 콘솔입니다. 최근 실 KOSIS API를 연결해 소비자물가의 실제 일치 판정을 확인했습니다. 다음 단계의 우선순위와 사업화 방향에 대해 조언을 구합니다.

## 1. 전체 프로젝트 관련

1. 지금 단계에서 “실 KOSIS 근거를 찾아 일치/판단불가를 설명한다”는 핵심 가치를 가장 설득력 있게 증명하려면, 다음 2주 동안 어떤 성공 지표를 하나만 우선해야 할까요? (예: Hit@k, 일치 판정 정확도, 검증자 작업시간 절감)
2. KOSIS 통계표 매핑 실패·복합 기사 문장·잠정치 문제를 고려할 때, MVP 범위를 어떤 지표군 또는 기사 유형으로 먼저 좁혀야 신뢰도를 만들 수 있을까요?
3. 자동 판정과 사람 검토의 경계를 현재처럼 보수적으로 두는 것이 적절한가요? 멘토님이 보시기에 자동 확정해도 될 조건과 반드시 검토를 거쳐야 할 조건은 무엇인가요?

## 2. 역할별 멘토링 질문

### R1 — PM·Evaluation

1. 골든셋과 릴리스 게이트를 설계할 때, 모델·매핑 품질뿐 아니라 사용자 신뢰를 측정할 핵심 평가 기준은 무엇이어야 할까요?
2. 50건 파일럿에서 250건 이상으로 늘리기 전에 반드시 확인할 “확장 중단 기준”은 무엇인가요?

### R2 — Claim 추출

1. 한 문장에 여러 제목 조각과 수치가 섞인 경우처럼, 자동 추출에서 제외할 기준을 규칙으로 어디까지 두고 언제 LLM 보조로 넘기는 것이 좋을까요?
2. 기사 문장에서 숫자·단위·비교 기준·시점을 추출할 때, 초기에는 어떤 필드를 정확도 우선으로 확보해야 후속 검증 품질이 가장 좋아질까요?

### R3 — Evidence·KOSIS 매핑

1. 단일 검색어보다 보조 검색어와 재정렬을 추가한 현재 방식에서, 통계표 매핑 품질을 높이는 가장 효과적인 다음 투자처는 별칭 사전, 표 메타 인덱스, 임베딩/리랭커 중 무엇일까요?
2. KOSIS의 다차원 분류값(objL), 월간·연간 입도, 잠정치/최종치 문제를 제품 UX에서 어떻게 설명해야 사용자가 “판단불가”를 신뢰할까요?

### R4 — Verdict·Service

1. “일치”, “불일치”, “판단불가” 외에 실무 검증자가 바로 행동할 수 있도록 추가해야 할 상태나 우선순위는 무엇일까요?
2. 잘못된 자동 불일치보다 판단불가를 우선하는 현재 정책은 어떤 영역까지 유지해야 하며, 언제 더 공격적인 자동화로 전환해도 될까요?

### R5 — Agent·운영 자동화

1. API 호출 예산, 실패 Claim 재시도, 감사 로그를 자동 운영할 때 최소한 어떤 관측 지표와 알림을 먼저 갖춰야 할까요?
2. 역할별 작업 로그와 에이전트 자동화가 팀 생산성을 높이는 실제 운영 루틴은 어떻게 설계하는 것이 좋을까요?

## 3. ClaFact 사업성·비즈니스 관련

1. 초기 고객은 언론사 팩트체크팀, 정책 연구기관, 공공기관 홍보/통계팀 중 어디를 우선 공략하는 것이 문제 적합성이 높을까요?
2. 고객이 “기사 수치 검증”에 실제 비용을 지불하게 만드는 핵심 가치는 정확도, 검증 시간 단축, 감사 가능성, 리스크 감소 중 무엇이며 이를 어떻게 숫자로 증명해야 할까요?
3. KOSIS 중심 MVP에서 출발해 다른 공식 데이터 소스까지 확장할 때, 유료 제품으로 차별화될 수 있는 데이터·워크플로우·검증자 협업 기능은 무엇일까요?
