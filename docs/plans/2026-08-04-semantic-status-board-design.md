# Semantic 검증 상태 보드 설계

> 상태: 승인됨 (2026-08-04)

## 목표

Shadow 실행 결과에서 현재 Claim이 어느 검증 단계까지 진행됐고, 다음에 어떤 행동을 해야 하는지를 한눈에 보여준다.

## 화면 구조

### 1. 현재 실행 파이프라인 보드

아래 5단계를 왼쪽에서 오른쪽으로 보여준다.

```text
Claim 구조화 → KOSIS 후보 탐색 → 표 매핑·Card 확정 → Evidence 스냅샷 → 원본값 판정
```

각 단계는 `완료`, `현재 작업`, `대기` 중 하나로 표시한다.

- 완료: 초록색
- 현재 작업: 파란색
- 대기: 회색

각 카드에는 `현재 건수 / 검증 후보 문장 수`를 함께 표시한다. 마지막 판정 단계에서는 일치·불일치·판정불가의 요약도 표시한다.

### 2. 다음 해야 할 일

파이프라인 바로 아래에 현재 상태에서 필요한 행동을 한 문장으로 표시한다.

- 후보 탐색이 없으면: `선택한 Claim의 “KOSIS 후보 3개 찾기”를 실행하세요.`
- 후보가 있고 표 매핑이 없으면: `후보 표를 선택하고 Semantic Card를 확인·저장하세요.`
- 표 매핑이 있고 스냅샷이 없으면: `선택 표의 KOSIS 원본값을 조회해 Evidence 스냅샷을 만드세요.`
- 스냅샷이 있고 최종 판정이 없으면: `원본값 대조를 실행해 판정을 확정하세요.`
- 완료 Claim이 있으면: `현재 Claim의 검증 흐름이 완료되었습니다.`

### 3. 보조 지표 분리

- `성장형 Semantic Catalog`와 `골든셋 E2E 전체 현황`은 파이프라인 보드 아래에 둔다.
- 골든셋은 현재 Shadow 실행의 결과가 아니라 검증 기준 데이터이므로 별도 제목과 안내문을 유지한다.

## 비범위

- Claim 분류, KOSIS 검색, 점수 계산, 저장소, 판정 로직은 변경하지 않는다.
- 이 변경은 기존 집계값을 읽는 UI 재구성이다.

## 완료 기준

1. `현재 구현된 Semantic 검증 상태`에 5단계 흐름이 보인다.
2. 각 단계에 상태·건수·색상 구분이 있다.
3. 다음 행동이 자동 문장으로 표시된다.
4. Catalog와 골든셋 지표는 현재 실행 흐름과 시각적으로 분리된다.
