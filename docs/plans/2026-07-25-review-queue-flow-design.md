# 검증자 리뷰 큐 흐름 정리 설계

## 문제

검증자 리뷰 큐의 모든 Claim에 공식 기관명·URL·시행일 입력이 노출된다. 그러나 이 입력은 공식 공지·조사 일정 Claim에만 유효하며, 일반 KOSIS 수치 판정에는 사용되지 않는다. 또한 자동 승인으로 마지막 큐 항목을 처리한 직후에도 “먼저 검증 탭에서…” 안내가 표시돼 승인 완료 상태를 설명하지 못한다.

## 화면 규칙

- 일반 KOSIS Claim: 판정 근거, `자동 판정 승인`, `판단 보류`만 표시한다.
- `OFFICIAL_ANNOUNCEMENT` Claim: 공식 기관명, 공식 공지 URL, 시행일, `공식 근거 교체 후 재검증`을 표시한다.
- 자동 승인 또는 보류 처리 직후에는 세션 단위 성공 메시지를 표시한다.
- 저장된 큐와 현재 세션 결과가 모두 없을 때에만 신규 검증 안내를 표시한다.
- 방금 처리 후 저장된 큐가 비었다면 `현재 검증자 리뷰 대기 항목이 없습니다.`를 표시한다.

## 데이터·상태

기존 `source_type`과 `apply_review`를 그대로 사용한다. 화면 상태용 `review_feedback`만 Streamlit 세션에 추가하며, DB 스키마나 판정 규칙은 바꾸지 않는다.

## 검증

- 공식 근거 입력은 `OFFICIAL_ANNOUNCEMENT` 분기 안에만 존재하는지 소스 계약 테스트로 확인한다.
- 일반 승인 후 성공 메시지와 빈 큐 메시지가 존재하는지 확인한다.
- 기존 리뷰 큐 읽기·공식 근거 교체·승인·보류 계약 테스트를 함께 실행한다.
