## 문제

KOSIS 후보 보강과 스냅샷 준비는 표별 HTTP 재시도와 `objL` 보완을 연속 수행한다. 한 표의 응답 지연이 화면 전체를 수 분간 막아 사용자가 진행 상태나 실패 원인을 알 수 없다.

## 결정

- UI 경로의 표별 HTTP 요청은 30초 이내에 끝나도록 시간과 재시도 횟수를 제한한다.
- 후보 보강 실패는 다른 후보의 정렬·표시를 막지 않고, 실패 사유를 후보 결과에 남긴다.
- 스냅샷 준비 실패는 연결 지연과 표 파라미터 보완 실패를 구분해 표시하고, 사용자가 재시도할 수 있게 한다.
- 성공한 스냅샷만 근거 저장 단계로 전달한다. 통계 정의와 적용 범위 확정은 계속 사람이 담당한다.

## 대안

백그라운드 작업으로 무제한 대기를 허용하는 방식은 Streamlit 세션의 취소·상태 관리 복잡도를 높인다. 이번 범위에서는 제한된 동기 조회와 명확한 재시도를 선택한다.

## 완료 기준

- 지연된 KOSIS 요청이 UI 조회 예산 안에서 종료된다.
- 후보 보강 중 한 표가 실패해도 나머지 후보는 표시된다.
- 스냅샷 준비 실패 메시지에 재시도 가능 여부와 원인이 포함된다.
- 기존 KOSIS 조회·스냅샷·후보 정렬 테스트가 유지된다.
