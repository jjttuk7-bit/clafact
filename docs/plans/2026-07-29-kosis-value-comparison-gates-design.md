# KOSIS 실제 값 대조 사전 검증 게이트 설계

## 목적

Shadow Mode에서 뉴스 수치 문장과 KOSIS 조회 스냅샷을 자동 대조할 때, 비교가 가능한 경우에만 `match` 또는 `mismatch`를 반환한다. 비교의 전제조건이 불명확하면 값을 추정하거나 결론을 내리지 않고 `not_comparable`로 기록한다.

## 결정

기간 → 지표 → 선택 조건 → 값 성격 → 단위 → 수치 순서의 단일 게이트 체인을 사용한다. 각 단계의 통과·실패 사유를 결과 객체와 CSV에 남긴다. 이 방식은 문장·근거·스냅샷을 같은 조건으로 묶은 뒤에만 숫자를 대조하므로, 운영 판정을 바꾸지 않는 Shadow 연구 원칙과 맞는다.

## 입력과 출력

입력은 다음으로 한정한다.

- 뉴스 문장과 기사 발행일
- 이미 선택·저장된 KOSIS 근거 객체의 핵심 지표와 선택 조건
- 변조하지 않은 KOSIS 조회 스냅샷

출력 상태는 기존과 동일하다.

| 상태 | 의미 |
| --- | --- |
| `match` | 모든 게이트가 통과했고 문장 값과 KOSIS 값이 허용오차 안에서 일치함 |
| `mismatch` | 모든 게이트가 통과했으나 값이 다름 |
| `not_comparable` | 하나 이상의 전제조건을 확정할 수 없어 실제값 대조를 하지 않음 |

## 게이트 규칙

1. **기간**: 문장 시점을 기사 발행일로 절대 시점으로 해석한 뒤 스냅샷 기간과 정확히 일치시킨다. `지난달` 같은 상대 시점은 기존 파서의 정규화 결과를 사용한다.
2. **지표**: 근거 객체의 선택 핵심 지표와 동일한 스냅샷 항목만 남긴다. 예를 들어 `전년동월비(%)`와 `전월비(%)`는 서로 대조하지 않는다.
3. **선택 조건**: 지역·지수종류 등 근거 객체에 저장된 선택값이 스냅샷 레코드와 모두 같아야 한다.
4. **값 성격**: 문장 수치와 공식 값이 모두 비율, 퍼센트포인트, 절대 수치 중 같은 성격이어야 한다. 비율과 퍼센트포인트를 혼동하면 대조하지 않는다.
5. **단위**: 같은 성격 안에서도 문장 단위와 KOSIS 단위가 호환되어야 한다. `%`와 `%p`는 서로 호환하지 않는다. 절대 수치는 기존 단위 문자열이 같을 때만 통과한다.
6. **수치**: 위 조건을 통과한 레코드의 KOSIS 값을 수치로 읽어 문장 값과 비교한다. 비율은 기존 0.05%p 허용오차를 적용하고, 절대 수치는 정확히 일치해야 한다.

## 기록 형식

비교 결과에는 사람이 읽을 수 있는 `reason` 외에 게이트별 결과 목록을 추가한다. 각 항목은 게이트명, 통과 여부, 근거 설명을 가진다. CSV에는 게이트 결과를 한 칸의 읽기 쉬운 텍스트로 내보낸다. 예: `기간: 통과(2025-10) | 지표: 통과(전년동월비(%)) | 단위: 실패(문장 %p, KOSIS %)`.

기존 SQLite 저장소는 결과 JSON 전체를 저장하므로 테이블 마이그레이션 없이 새 필드를 보존할 수 있다.

## 화면 동작

`KOSIS 실제 값 대조` 버튼과 기존 세 상태 표시는 유지한다. 결과 아래에 “대조 게이트”를 보여 줘 사용자가 어떤 조건 때문에 대조되거나 중단되었는지 바로 확인할 수 있게 한다. `not_comparable`는 오류가 아니라 안전한 연구 기록으로 표시한다.

## 오류 처리

- 수치가 없거나 기간을 해석하지 못하면 첫 실패 게이트와 함께 `not_comparable`
- 스냅샷이 없거나 공식 값이 수치가 아니면 해당 게이트에서 중단
- 서로 다른 값 성격 또는 단위면 값을 비교하지 않음
- 입력값·기존 스냅샷은 변경하지 않음

## 테스트

테스트는 다음을 보장한다.

- `지난달`의 기사 날짜 기반 월 해석 후 동일 기간 수치 일치
- `전년동월비`와 `전월비`가 다르면 지표 게이트에서 중단
- `%p` 문장과 `%` KOSIS 값은 단위/값 성격 게이트에서 중단
- 모든 조건이 맞으면 기존과 같이 `match`/`mismatch`
- 게이트 기록이 결과 JSON과 CSV에 포함됨
