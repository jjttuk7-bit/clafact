# 검증 실험실 통합 EDA 고도화 설계

## 목적

검증 실험실에 업로드한 CSV의 전반적인 품질, 기사 구조, 수치 주장 특성을 한 화면에서 파악한다. EDA는 운영 Claim·리뷰 큐·KOSIS 판정 이력에 영향을 주지 않으며 HCX API를 자동 호출하지 않는다.

## 핵심 원칙

- 업로드 CSV 행의 기사와 본문에서 분리한 문장만 사용한다.
- 업로드 문서에 없는 기사·문장·수치·근거를 생성하지 않는다.
- EDA 계산은 Python 규칙만 사용한다.
- 운영 DB와 연구 DB에 업로드 원문을 저장하지 않는다.
- 표본 수에 맞는 시각화를 사용한다. 기사 1건에는 분포 차트를 표시하지 않는다.
- 최대 1,000건은 전체 분석하고, 초과하면 사용자가 분석 범위를 선택하기 전 자동 실행하지 않는다.

## 데이터 흐름

```text
CSV 원본 행
→ 열 매핑과 인코딩 확인
→ 결측·날짜·중복 검사
→ 본문 경계 정제
→ 문장 분리와 Python 수치 주장 분석
→ 전체 EDA 요약
→ 선택 기사 상세
```

EDA 결과는 업로드 파일 해시와 분석 범위를 기준으로 세션에서 재사용한다. 파일이나 범위가 바뀌면 이전 분석 결과와 기사 선택 상태를 폐기한다.

## 분석 영역

### 1. 데이터 품질

- 원본 행, 유효 기사, 제외 기사, 중복 기사
- 제목·본문·날짜 결측
- 날짜 파싱 오류
- 본문 경계 정제 후 빈 기사
- 제외·경고 사유별 건수
- 문제가 있는 원본 행 번호와 사유

### 2. 기사 구조

- 정제 전후 본문 길이와 제거 문자 수·제거율
- 기사별 문장 수
- 평균, 중앙값, 최소, 최대, 사분위수
- IQR 기준 본문 길이·문장 수 이상치
- 기사 2건 이상일 때 길이 구간과 문장 수 분포
- 기사 1건일 때 선택 기사의 정제 전후 카드

### 3. 수치 주장 특성

- 전체 문장
- 수치 표현 포함 문장
- Python 후보 문장
- KOSIS 라우팅 문장
- 기사별 수치 후보 수
- 수치 유형: 백분율, 금액, 인원, 배수·건수, 기타
- 시점: 과거, 현재, 전망, 불명
- 주장 유형과 라우팅 결과 분포

HCX 결과는 업로드 EDA에 포함하지 않는다. HCX 관련 통계는 사용자가 실제 비교를 실행해 연구 이력에 저장한 결과만 별도 영역에서 다룬다.

### 4. 기사 탐색과 상세

기사를 품질 문제, 본문 길이, 수치 후보 수로 필터링한다. 선택 기사에는 다음 항목을 표시한다.

- 원본 행 번호, 제목, 날짜
- 정제 전후 길이, 제거 문자 수, 문장 수, Python 후보 수
- 저장된 문장별 원문
- 추출 수치, 해석 시점, 주장 유형, 라우팅, Python 규칙 근거

## 화면 구성

하나의 `CSV 통합 EDA` 영역을 네 구역으로 나눈다.

1. 품질 KPI 카드와 제외 사유 가로 막대
2. 기사 구조 통계와 표본 수에 맞는 분포 차트
3. 전체 문장 → 수치 포함 → Python 후보 → KOSIS 라우팅 흐름과 특성 분포
4. 문제 기사 표와 선택 기사 문장 상세

대시보드에는 원본 행 번호를 유지하고 기술 필드나 전체 원문을 불필요하게 브라우저로 보내지 않는다.

## 대용량 처리

- 1,000건 이하: 업로드 직후 전체 EDA 수행
- 1,000건 초과: 분석 범위 선택 UI를 먼저 표시
- 선택 범위만 문장 분리와 Python 규칙 분석
- 차트는 집계 데이터만 전달하고 문제 행 표는 페이지 또는 제한된 행으로 표시
- 계산 결과는 파일 해시와 범위에 묶어 재사용

## 오류 처리

- UTF-8/UTF-8 BOM이 아니면 인코딩 오류를 표시한다.
- 빈 CSV와 본문 열 부재를 구분한다.
- 날짜 오류는 기사를 버리지 않고 품질 경고로 기록한다.
- 본문 부재와 정제 후 빈 본문은 실행 대상에서 제외하고 사유를 기록한다.
- EDA 내부의 한 행 오류가 전체 파일 분석을 중단하지 않도록 행 단위 오류로 수집한다.

## 테스트 기준

- 정상 1건 CSV에서 분포 차트 대신 상세 카드가 선택된다.
- 빈 CSV, 본문 열 부재, 중복, 날짜 오류, 본문 경계 제외가 정확히 집계된다.
- 1,001건은 범위 선택 전 분석되지 않는다.
- 정제 전후 길이와 제거 문자 수가 원문 기준으로 일치한다.
- 문장, 수치 유형, 시점, 주장 유형, 라우팅 분포가 입력 문장에서만 계산된다.
- IQR 이상치와 기사 필터가 결정적으로 동작한다.
- 업로드 원문 밖의 문장이 결과에 나타나지 않는다.
- HCX와 운영 DB가 호출되지 않는다.

## 범위 제외

- EDA 업로드만으로 HCX API 호출
- 자동 KOSIS 사실 검증
- 업로드 원문 전체의 영구 저장
- 자연어 기반 자동 분석 보고서 생성
