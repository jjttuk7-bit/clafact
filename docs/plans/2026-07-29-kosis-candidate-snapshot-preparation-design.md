# KOSIS 후보 적용 뒤 자동 조회·스냅샷 준비 설계

## 목적

Shadow Mode에서 사용자가 KOSIS 후보를 선택한 뒤 수행해야 했던 메타데이터 자동 채우기 단계를 하나의 명확한 준비 동작으로 묶는다. 근거 저장과 실제값 대조는 사용자가 명시적으로 실행한다.

## 사용자 흐름

1. 사용자가 Shadow 문장을 고르고 KOSIS 후보를 탐색한다.
2. 사용자가 후보를 선택해 **근거 입력에 적용**한다.
3. 근거 입력 영역은 표 ID·원본 URL·후보 제목·선택 항목을 채운 상태가 된다.
4. 사용자가 **KOSIS 조회·스냅샷 준비**를 누른다.
5. 시스템은 공식 KOSIS API로 최신 행을 한 번 조회해 메타데이터 초안을 채우고, 불변 조회 스냅샷을 임시 준비한다.
6. 사용자가 **KOSIS 근거 저장**을 누르면 근거 객체와 준비된 스냅샷이 함께 연구 저장소에 보존된다.
7. 저장된 근거를 Shadow 문장에 연결한 후 **KOSIS 실제 값 대조**를 실행한다.

## 경계

- 준비 버튼은 공식 API 조회와 화면 초안·세션 스냅샷 준비까지만 수행한다.
- 근거 객체·스냅샷을 영구 저장하지 않으며, 운영 Claim·리뷰·판정도 변경하지 않는다.
- 통계 정의는 자동 추정하지 않는다.
- 준비 실패는 저장되지 않으며 API 오류를 화면에만 명확히 표시한다.

## 화면

기존 `KOSIS 메타데이터 자동 채우기`를 `KOSIS 조회·스냅샷 준비`로 바꾼다. 버튼 아래에는 준비 상태를 표시한다.

- 준비 전: “후보를 적용한 뒤 공식 조회를 준비하세요.”
- 준비 성공: “공식 API 조회 완료 · 스냅샷 N건 준비됨 · 근거 저장 시 함께 보존됩니다.”
- 준비 실패: “KOSIS 조회·스냅샷 준비 실패: …”

후보를 적용하는 성공 메시지도 다음 행동을 직접 안내한다: “근거 입력에서 KOSIS 조회·스냅샷 준비를 계속하세요.”

## 재사용 컴포넌트

- `parse_kosis_table_identity`: 표 ID·URL의 기관 ID와 표 ID 검증
- `HttpKosisClient.fetch_data`: 공식 API 조회
- `autofill_from_rows`: 제목·기관·지표·차원·주기·단위 초안 생성
- `classify_table_structure`: 구조 유형과 근거 생성
- `build_evidence_snapshot`: 불변 스냅샷 조립
- 기존 `KOSIS 근거 저장`: 근거 객체와 준비된 스냅샷 영구 저장

## 테스트

- 준비 성공 시 API 행으로 메타데이터 필드와 스냅샷 컨텍스트가 설정됨
- 준비 실패 시 저장 컨텍스트를 만들지 않고 오류가 표시됨
- 후보 적용 문구와 준비 버튼이 현재 단계로 연결됨
- 기존 저장 동작은 준비된 스냅샷을 함께 보존하는 기존 계약을 유지함
