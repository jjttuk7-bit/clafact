## 목적

R2·R3가 다음 주 완성할 골든셋 30~50건을 기준으로, ClaFact의 통계표 추천과 최종 판정이 매주 얼마나 정확한지 같은 방식으로 기록한다. 골든셋 자체는 R2·R3의 작업물을 원본으로 사용하며, 이 문서는 이를 중복 생성하거나 소유하지 않는다.

## 기록 위치

`docs/quality/weekly_mapping_quality.md`를 주간 품질 기록의 기준 문서로 둔다. 각 주차는 같은 문서의 새 섹션으로 추가해 추이를 비교한다. 골든셋의 원본 위치·형식·담당자는 R2·R3 확정본을 받은 뒤 연결한다.

## 측정 항목

| 항목 | 의미 | 계산 방식 |
|---|---|---|
| 평가 표본 수 | 이번 주에 실제로 평가한 골든셋 Claim 수 | 평가 완료 Claim 수 |
| Hit@1 | 첫 번째 추천 통계표가 사람이 확인한 정답 통계표인 비율 | 1순위 정답 수 / 평가 표본 수 |
| Hit@3 | 상위 세 추천 통계표 안에 정답 통계표가 포함된 비율 | 상위 3개 내 정답 수 / 평가 표본 수 |
| 판정 일치율 | 자동 판정이 사람이 정한 기대 판정과 같은 비율 | 동일 판정 수 / 판정 가능 표본 수 |
| 판단불가 비율 | 자동 검증이 근거 부족·입도 불일치 등으로 보류된 비율 | 판단불가 수 / 평가 표본 수 |

`판정 가능 표본`은 골든셋에서 사람이 일치·불일치·판단불가 기대 결과를 확정한 Claim만 뜻한다. 통계표 정답이 아직 없는 Claim은 Hit@ 측정에서 제외하고 이유를 남긴다.

## 운영 흐름

1. R2·R3가 확정한 골든셋 원본과 정답 통계표·기대 판정을 받는다.
2. R1이 표본 수, Hit@1·Hit@3, 판정 일치율을 계산해 주간 문서에 기록한다.
3. R2·R3는 실패 사례를 `검색어/통계표 후보/기간·단위` 관점에서 분류한다.
4. R4·R5는 자동 판정·재검증·오류 처리에서 나온 운영 문제를 기록한다.
5. 팀은 다음 주 개선 항목을 최대 세 건으로 정하고, 다음 기록에서 결과를 비교한다.

## 역할

| 역할 | 책임 |
|---|---|
| R1 (평가·품질 관리) | 측정 기준, 주간 수치, 추이와 개선 우선순위 관리 |
| R2 (Claim 추출) | Claim 품질과 복합 Claim 등 입력 실패 사례 분류 |
| R3 (근거 매핑) | 정답 통계표와 추천 통계표 차이, 검색·매핑 개선안 정리 |
| R4 (판정 서비스) | 일치·불일치·판단불가 판정 규칙과 사람 검토 결과 관리 |
| R5 (운영 자동화) | 재검증, 오류 로그, 측정 실행의 안정성 관리 |

## 완료 기준

- 골든셋 원본의 소유자와 위치를 품질 기록에 연결한다.
- 첫 주 측정에서 표본 수와 Hit@1·Hit@3을 기록한다.
- 판정 일치율과 판단불가 비율을 기록한다.
- 실패 사례와 다음 주 개선 항목을 각각 최소 한 건 이상 남긴다.
