## 목적

운영 검증과 분리된 화면에서 동일한 뉴스 입력을 Python 규칙, LLM 단독, 하이브리드 엔진으로 각각 실행하고, 탐지·구조화 결과와 실행 비용을 비교한다. 이 기능은 운영 Claim·리뷰 큐·판정 이력을 변경하지 않는다.

## 선택한 방식

사이드바에 `검증 실험실` 메뉴를 추가한다. 한 번의 실행에서 세 방식을 모두 계산해 같은 행으로 비교한다. LLM이 사용할 수 없는 환경에서는 해당 열에 원인을 표시하되 Python/하이브리드 비교 화면 자체는 유지한다.


### 내비게이션 배치

`검증 실험실`은 운영 절차를 구성하는 `검증`과 `검증자 리뷰` 사이에 두지 않는다. 운영 DB와 분리된 비교·실험 기능임을 명확히 하기 위해, 사이드바의 마지막 항목인 `자산 현황` 뒤에 배치한다.
## 데이터 흐름

### CSV 기사 선택

기존 기사 CSV의 본문 별칭(`body`, `본문`, `content`, `text`)과 선택적 제목·작성일 열을 그대로 사용한다. 업로드한 CSV는 검증 실험실의 세션에서만 읽고 `Store`나 운영 Claim 흐름에 저장하지 않는다.

파일에 1,000건 이상이 있어도 자동 일괄 실행하지 않는다. 유효 본문을 가진 기사를 제목·작성일과 함께 페이지 목록으로 보여 주고, 사용자가 고른 한 기사만 세 방식 비교에 전달한다. 한 행 CSV도 같은 선택 흐름으로 처리하므로 개별 기사 파일 업로드에 사용할 수 있다.

대량 일괄 비교와 결과 다운로드는 이 단계의 범위에서 제외한다. LLM 호출 비용과 Streamlit 세션 시간을 예측 가능하게 유지한다.

### 실행 모드와 판단 근거

실험실은 다음 네 실행을 제공한다.

- **전체 비교**: Python, LLM, 하이브리드를 서로 독립 실행하고 각 방식의 탐지 수·LLM 호출 수·경과시간과 전체 경과시간을 분리해 표시한다.
- **Python만**, **LLM만**, **하이브리드만**: 선택한 한 방식만 실행하고 그 방식의 시간만 기록한다.

전체 비교의 방식별 시간은 다른 방식 호출을 포함하지 않는다. 특히 LLM 호출 시간이 Python 규칙 실행 시간으로 보이지 않도록 한다.

모든 실행 결과에는 각 문장의 판단 근거를 제공한다. Python은 추출 수치·시점·유형·라우팅, LLM은 판정과 사유, 하이브리드는 Python 1차 관문과 LLM 2차 사유를 표시한다. 실험실은 KOSIS 표 검색·공식 출처 판정은 호출하지 않는다.

1. 사용자가 기사 본문과 발행일을 입력한다.
2. Python 방식은 기존 `detect.is_candidate`, `parse_claim`, `source_classify.classify`를 사용한다.
3. LLM 방식은 문장마다 `detect_llm.judge`를 호출한다. 이 버전은 LLM이 ‘검증 가능한 수치 주장인가’를 판별한 결과와 사유를 비교 대상으로 제공한다.
4. 하이브리드는 Python 후보만 LLM 2차 판별에 통과시킨다. LLM 호출 실패 시 Python 후보를 보수적으로 유지한다.
### 업로드 원문 경계 보장

검증 실험실은 업로드 CSV 밖의 뉴스 기사나 문장을 생성·추가하지 않는다. 선택 가능한 기사는 업로드 행의 본문 셀에서 정제한 문자열만 원천으로 사용하며, 결과 문장은 그 문자열에서 분리된 경우에만 표시한다.

크롤링된 본문에 `관련 기사`, 기자 프로필, 구독·푸터 같은 종료 표식이 있으면 가장 이른 표식에서 본문을 자른다. 정제 후 본문이 비거나 경계를 안전하게 적용할 수 없는 행은 비교 실행 대상에서 제외하고 사유를 표시한다.

LLM은 업로드된 문장의 탐지 가능성만 판정한다. 새 뉴스 문장·수치·출처를 생성하거나 결과 행으로 추가하지 않는다.

5. 실험 결과는 `st.session_state`에만 보관한다. `Store.enqueue_claim`, `process_pending`, KOSIS 검증, 리뷰 승인 기능을 호출하지 않는다.

### 관측성·EDA 고도화

실행 결과는 Python·LLM·하이브리드 세 카드로 항상 표시한다. 단독 실행 시 선택하지 않은 방식은 `미실행`으로 표시하고, 전체 비교는 세 방식 모두의 결과를 채운다. 시간은 각 방식의 독립 경과시간과 전체 비교 경과시간을 `초 (ms)` 단위로 함께 표시한다.

문장별 근거는 방식별로 구분한다. Python은 수치 표현·시점·주장 유형·라우팅과 후보 규칙, LLM은 원문 입력에 대한 판정 사유·호출 상태, 하이브리드는 Python 1차 관문과 LLM 2차 판단 또는 미호출 사유를 표시한다.

CSV EDA는 업로드 세션에만 한정한다. 원본 행·유효 기사·경계 제외·제거 문자 수·본문/문장 길이를 집계하고, 선택 기사의 정제 전후 길이와 탐지 결과 분포를 기본 차트로 보여 준다.

## 화면 구성

- 상단: 운영 DB에 저장하지 않는다는 고지와 방식별 역할 설명
- 입력: 기사 본문, 발행일, 실행 버튼
- 요약: 방식별 탐지 수, LLM 호출 수, 처리 시간
- 표: 문장, Python 결과, LLM 결과/사유, 하이브리드 결과, 차이 여부
- 상세: Python이 추출한 수치·시점·라우팅 결과와 LLM 사유

## 안전 및 품질 원칙

- LLM 결과는 검증 완료나 최종 판정을 만들지 않는다.
- LLM 단독 결과도 원문 문장을 넘어선 수치·통계표·근거를 생성하지 않는다.
- API 키·LLM 설정이 없으면 화면은 오류가 아닌 ‘LLM 미사용’ 상태를 명시한다.
- 비교 화면은 운영 DB를 열거나 쓰지 않아야 한다.

## 범위 제외

- 이번 단계에서는 실험 실행 이력을 SQLite에 영구 저장하지 않는다.
- KOSIS 표 검색·최종 판정의 3방식 비교는 다음 단계에서 Claim 구조화 스키마와 골든셋이 준비된 뒤 추가한다.
- LLM이 수치·지표를 JSON으로 완전 추출하는 기능은 별도 실험으로 확장한다.
