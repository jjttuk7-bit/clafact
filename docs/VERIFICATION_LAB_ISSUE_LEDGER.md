## 목적

이 문서는 ClaFact 검증 실험실과 연결된 기능에서 발견된 문제, 그 증거, 원인, 조치, 미해결 과제를 한곳에 누적하는 공식 학습 원장이다. 운영 Claim·리뷰 큐·KOSIS 판정 이력과는 분리한다.

과거 항목은 Git 이력과 작업 대화에서 재구성했으므로 `Backfilled`로 표시한다. 미래 항목은 문제가 확인되는 즉시 추가하며, 해결 여부는 테스트 또는 재현 증거로 갱신한다. 추측은 사실처럼 기록하지 않는다.

## 상태 정의

- `Resolved`: 조치와 검증 증거가 있다.
- `Monitoring`: 조치는 했으나 실제 사용 데이터에서 관찰이 더 필요하다.
- `Open`: 재현되었지만 아직 해결하지 않았다.
- `Baseline`: 기존 문제이며 현재 변경의 회귀가 아님을 확인했다.

## 핵심 원칙

1. 업로드한 기사 본문 밖의 문장, 기사 추천·기자 프로필·구독 안내는 후보로 생성하지 않는다.
2. `후보 탐지`, `공식 근거 충분성`, `최종 사실 판정`은 서로 다른 단계다. 후보 미탐지로 근거 부족을 표현하지 않는다.
3. 모델 비교 결과에는 제공자·모델·실행 모드·호출 수·경과 시간·오류 여부를 함께 남긴다. API 키와 원문 외 민감 정보는 기록하지 않는다.
4. 모든 변경은 해당 문제 ID, 커밋, 테스트(또는 수동 재현 증거)를 연결한다.
5. **“실패의 기록은 프로젝트의 가치를 높인다.”** 성공과 실패를 모두 남기되, 특히 실패는 입력·실행 모드·증상·원인·보호 동작·후속 실험을 재현 가능하게 기록한다.

## 상세 기록

### VLAB-009 — HCX가 후보 문장 2번을 미탐지

- **증거:** 2026-07-26 화면 공유. 대상 문장에는 `2.6%`, `지난해 7월`, `15개월`, `가장 높은`이 포함된다.
- **영향:** 실제 검증할 수치·비교 주장이 후보군에서 빠져 재현율이 낮아진다.
- **현재 원인 가설:** 현재 HCX 프롬프트가 “공식 통계로 검증 가능한 수치 주장”을 한 번에 판단해, 후보 여부와 기사 안의 직접 공식 출처 인용 여부를 혼동한다.
- **확정 판단:** 후보 탐지 결과는 `탐지`가 맞다. 이 문장만으로 실제 수치의 참·거짓 또는 공식 근거 확보가 확정되는 것은 아니다.
- **해결:** HCX 프롬프트와 응답 계약을 `candidate`, `candidate_reason`, `evidence_status`, `evidence_reason`, `quoted_spans`로 분리했다. `needs_retrieval`은 후보 탈락이 아닌 정상 탐지 상태다.
- **검증:** `tests/test_detect_llm.py::test_judge_decision_keeps_comparative_numeric_claim_as_candidate`, `tests/test_experiment_lab.py::test_hcx_mode_preserves_candidate_and_evidence_status_separately`가 이 문장을 `candidate=true`, `needs_retrieval`로 고정한다.
- **후속 관찰:** 실 API HCX-005 응답의 JSON 준수율과 원문 인용 구간의 정확도는 골든셋 확장 시 계속 관찰한다.

### VLAB-010 — 제공자·모델이 드러나는 비교 체계

- **현재 확인:** 화면의 `HCX 실호출` 조건은 `CLAFACT_HCX_MODE=live` 및 `HCX_API_KEY` 설정이다. 이때 `HcxClient`가 CLOVA Studio의 HCX Chat Completions API를 호출하며, 기본 모델 값은 `HCX-005`다.
- **한계:** 현 화면만으로 각 호출의 HTTP 성공 상태, 모델 변경 여부, 요청 식별자, 원문 응답 파싱 실패를 충분히 감사할 수 없다.
- **목표 구조:** `provider=HCX`, `model=HCX-005`처럼 제공자와 모델을 결과 객체에 보관한다. GPT를 추가할 때는 동일 스키마의 `provider=OpenAI`, `model=<선택 모델>` 실행을 별도 열로 추가하며, HCX 결과를 덮어쓰지 않는다.
- **금지:** API 키, Authorization 헤더, 원문에 없는 문장을 로그나 화면 근거로 생성하지 않는다.

### VLAB-012 — 하이브리드의 성공과 구조적 한계

- **증거:** 2026-07-26 동일 기사 14문장 실행 화면 `20260726_114052.png`, `20260726_114004.png`, `20260726_114223.png`. Python 단독은 `13/14`, HCX 단독은 `11/14`, 하이브리드는 `13/14`였다.
- **성공 1 — 의미 판정 보강:** 2번 문장은 Python이 수치·비교 규칙으로 후보를 잡고, 하이브리드의 HCX가 `탐지`와 `검색 필요`를 분리했다. 이는 규칙 탐지 뒤에 의미 해석과 근거 상태를 붙이는 하이브리드의 실질 가치다.
- **성공 2 — 장애 내성:** HCX JSON 응답이 없거나 파싱에 실패한 문장에서도 하이브리드는 Python 후보를 보수적으로 유지했다. HCX 단독의 일시적 실패가 전체 재현율 하락으로 번지는 것을 막았다.
- **실패/한계:** 현재 하이브리드는 Python 후보 문장에만 HCX를 호출하는 직렬 게이트다. 따라서 Python이 놓친 문장은 HCX가 판별할 기회 자체가 없으며, `Python=false, HCX=true` 사례를 현재 하이브리드 실행으로는 발견할 수 없다.
- **해석:** 현재 구현은 `상호 보완형 결합`이 아니라 `Python 재현율 + HCX 의미 보강/오류 안전망`이다. 하이브리드가 Python보다 더 높은 재현율을 내는 설계는 아직 아니다.
- **후속 실험:** 검증 실험실에서는 모든 문장을 Python과 HCX에 독립 실행해 다음 네 집합을 집계한다.
  1. `P+ / H+`: 양쪽 모두 탐지
  2. `P+ / H-`: Python만 탐지 또는 HCX 오류
  3. `P- / H+`: HCX만 탐지 — 하이브리드 확장의 핵심 학습 자산
  4. `P- / H-`: 양쪽 모두 미탐지
- **설계 후보:** 연구용 하이브리드의 후보 합집합은 `Python OR HCX`로 구성하고, 운영용 하이브리드는 비용·오탐 위험을 평가한 뒤 별도로 결정한다. `P- / H+`는 자동 정답으로 간주하지 않고 사람이 원문을 검토해 골든셋에 편입한다.
- **상태:** Open. 이번 화면은 직렬 하이브리드의 가치를 입증했지만, Python 미탐지를 HCX가 복구하는 상호 보완형 설계는 아직 구현·검증되지 않았다.

### VLAB-013 — 동일 문장의 HCX JSON 응답 불안정

- **증거:** HCX 단독 화면에서 2번 문장은 `미사용 · 판별 응답 파싱 실패`, `확인 불가 · HCX JSON 응답이 없습니다`로 표시됐다. 별도 하이브리드 화면에서는 같은 문장이 `탐지`, `검색 필요`와 원문 인용까지 정상 반환됐다. 하이브리드의 다른 문장에서도 JSON 파싱 실패 후 Python 보수 유지가 관찰됐다.
- **확정된 사실:** 실행마다 구조화 응답 성공 여부가 달랐다. HCX 단독의 `11/14`는 순수한 의미 분류 성능과 응답 실패가 섞인 수치다.
- **미확정 원인:** 빈 API 응답, 응답 포맷 이탈, 전송 오류, 제한/쿼터, 응답 절단 중 어느 것인지는 현재 화면만으로 확정할 수 없다.
- **영향:** HCX 탐지율을 실제 모델 품질보다 낮게 측정하며, 동일 입력 재현성을 훼손한다.
- **후속 조치:** HTTP 상태, 요청 ID, 모델, 응답 길이, 원문 응답 해시, JSON 파싱 결과, 재시도 횟수를 비밀정보 없이 실행별로 기록한다. 빈 응답·포맷 오류는 의미상 `미탐지`가 아닌 `실행 실패`로 집계하고 제한된 재시도 정책을 별도로 시험한다.
- **상태:** Open. 관측성 데이터가 확보될 때까지 원인을 단정하지 않는다.
